## פרוטוקול שמירה

כל תלמיד עובד בתיקייה אישית קבועה במחשב, וקובצי הנתונים שלו יושבים בתוכה ולא זזים. Power BI זוכר את המיקום המלא של קובץ הנתונים, ולכן קובץ שהוזז או ששמו שונה שובר את הרענון.

שתי תתי-תיקיות לכל תלמיד, עם שם באנגלית ובלי רווחים. נתיב שכולו באותו כיוון כתיבה קל לקרוא ולהעתיק מהלוח:

```
Documents\PBI_Course\Cohen_Noa\data
Documents\PBI_Course\Cohen_Noa\work
```

ב-data נמצאים קובצי הנתונים שהמורה מחלק, וב-work קובצי Power BI של התלמיד. בכל שיעור נוצר קובץ חדש עם מספר השיעור, כך שתמיד יש גרסה קודמת לחזור אליה:

```
L01_Portal_Cohen_Noa.pbix
L02_Portal_Cohen_Noa.pbix
L03_Portal_Cohen_Noa.pbix
L04_BRFSS_Cohen_Noa.pbix
L05_BRFSS_Cohen_Noa.pbix
L06_BRFSS_Cohen_Noa.pbix
L07_Portal_Cohen_Noa.pbix
```

תחילת שיעור, שתי דקות:

1. פותחים את התיקייה work.
2. פותחים את הקובץ של השיעור הקודם.
3. File → Save as, באותה תיקייה, עם מספר השיעור של היום.

סוף שיעור, שתי דקות:

1. Ctrl+S.
2. בודקים שהקובץ מופיע ב-work עם מספר השיעור של היום.
3. סוגרים את Power BI. אם הוא שואל על שינויים שלא הוחלו, בוחרים Apply.

בדיקה אחת לפני השבוע: שומרים קובץ ניסיון ב-Documents, מפעילים את המחשב מחדש ובודקים שהקובץ נשאר. יש מחשבים שמוחקים קבצים בכל הפעלה מחדש. אם זה מה שקורה, צריך מקום אחר לתיקייה האישית (דיסק און קי או אחסון ענן של בית הספר), ומתאימים את הפרוטוקול לפני שיעור 1.

קובצי נקודת שמירה של המורה: בסוף החזרה על כל שיעור שומרים עותק בשם CP\_L01.pbix עד CP\_L07.pbix, בתיקיית מורה ובמקום נוסף מחוץ למחשב. תלמיד שאיבד קובץ, או שישב הפעם ליד מחשב אחר, ממשיך מהעותק.

תלמיד שלא מוצא את הקובץ:

1. ב-Power BI: File → Recent. ייתכן שהקובץ נשמר במקום אחר.
2. מחפשים בתיקייה Documents קבצים ששמם מסתיים ב-pbix.
3. מעתיקים את קובץ נקודת השמירה של השיעור הקודם ל-work, פותחים ושומרים בשם עם השם של התלמיד.
4. אם מופיעה שגיאה שקובץ הנתונים לא נמצא: בלשונית Home, בחץ שליד Transform data, בוחרים Data source settings → Change Source → Browse. בוחרים את קובץ ה-xlsx בתיקייה work של התלמיד, ואז OK → Close → Apply changes.

אם כיתה אחרת עובדת על אותם מחשבים, התיקייה האישית שומרת על הקבצים של כל תלמיד בנפרד. כלל אחד לכולם: לא פותחים ולא מוחקים תיקייה של מישהו אחר.

ארבעה קבצים מספיקים לכל השבוע. שלושת קובצי Portal מצורפים לשיחה, ואת BRFSS צריך להוריד בעצמך, כי ההורדה נחסמה בסביבה שלי.

| Portal\_rodents\_2016\_2026.csv | לכידות מ-2016, משחרור 6.109.0, כל העמודות בלי שינוי | 15,120 × 31 | 1 עד 3, 7 |

הורדת BRFSS\_PA.csv: פותחים את [הקישור להורדה](https://data.cdc.gov/resource/hn4x-zwk7.csv?$select=yearstart,yearend,locationabbr,locationdesc,datasource,class,topic,question,data_value_unit,data_value_type,data_value,data_value_alt,data_value_footnote_symbol,data_value_footnote,low_confidence_limit,high_confidence_limit,sample_size,total,age_years,education,sex,income,race_ethnicity,classid,topicid,questionid,datavaluetypeid,locationid,stratificationcategory1,stratification1,stratificationcategoryid1,stratificationid1&$where=classid=%27PA%27&$limit=100000) בדפדפן ושומרים בשם BRFSS\_PA.csv. אם הדפדפן מציג טקסט במקום להוריד, שומרים ב-Ctrl+S. בפתיחה ב-Excel השורה האחרונה צריכה להיות 60,061 (כולל שורת הכותרות). מספר קטן יותר אומר שההורדה נקטעה.

למה הקישור הזה ולא כפתור Export בדף המאגר: בעמודת המיקום יש שבירת שורה בתוך הערך, ובהגדרה לא נכונה Power Query מפצל בגללה שורות. הקישור מוריד רק את שאלות הפעילות הגופנית ומדלג על העמודה הזו, וכך גם קטן בערך בחצי. שמות העמודות יופיעו באותיות קטנות (yearstart ולא YearStart). אם בכל זאת משתמשים בקובץ המלא, בצעד Source מגדירים Line breaks ל-Ignore quoted line breaks ובודקים 118,580 שורות.

חלוקה לתלמידים דרך המודל: בשיעור 1 כל תלמיד מוריד לתיקייה data שלו את Portal\_rodents\_2016\_2026.csv ואת Portal\_species.csv, בשיעור 4 את BRFSS\_PA.csv, ובשיעור 7 את קובץ העדכון. בכל אחד מהם התלמיד שומר את ה-CSV שהוריד גם כקובץ xlsx בתיקייה work, ו-Power BI טוען את ה-xlsx. ה-CSV נשאר ב-data כגיבוי של המקור. הקבצים עצמם נמצאים במסע ההכנה, באזור ההורדות.

## שיעור 1: מה זו שורה אחת?

בסוף השיעור התלמידים יודעים ששורה בקובץ היא רישום אחד: בדרך כלל לכידה של חיה, ולפעמים הערה על חלקה שנמצאה ריקה או שלא נבדקה. היא לא בהכרח חיה אחת. ב-Power BI הם טוענים קובץ CSV, בונים כרטיס אחד ושומרים במקום הנכון.

התפיסה המוטעית שמתמודדים איתה: מספר השורות הוא מספר החיות. מושגים שצריך לדעת להסביר: רשומה, ישות, מפתח ראשי, מזהה, משתנה כמותי ומשתנה קטגוריאלי.

| דקות | שלב | מה קורה |
| --- | --- | --- |
| 0 עד 5 | פתיחה | סיפור הניסוי והשאלה "כמה חיות נלכדו מאז 2016?". כל תלמיד כותב ניחוש |
| 5 עד 15 | הדגמה | טעינה, Table view, כרטיס, שמירה |
| 15 עד 38 | תרגול | משימות א עד ד בצ'קליסט של התלמיד |
| 38 עד 45 | סיכום | כרטיס יציאה, שמירה, בדיקת תיקיות |

הסיפור לפתיחה: מאז 1977 חוקרים לוכדים מכרסמים במדבר של אריזונה, ב-24 חלקות מגודרות. בכל חלקה 49 מלכודות ברשת של 7 על 7, ופעם בחודש, סמוך לירח החדש, כל חלקה נבדקת לילה אחד. בחלקות הביקורת הפתחים בגדר גדולים. בחלקות אחרות הם קטנים מדי לחולדות קנגורו, שהגולגולת שלהן רחבה מדי, בגלל חללי אוזן מוגדלים. בחלקות ההרחקה המלאה אין פתחים בכלל.

ההדגמה, צעד אחר צעד:

1. פותחים Power BI Desktop וסוגרים את מסך הפתיחה, או בוחרים Blank report.
2. שומרים את קובץ המקור בגרסת Excel: פותחים את Portal\_rodents\_2016\_2026.csv ב-Excel, File → Save As → Excel Workbook, בתיקייה work בשם Portal\_rodents\_2016\_2026.xlsx. ה-CSV נשאר ב-data.
3. Home → Get data → Excel workbook, ובוחרים את ה-xlsx מהתיקייה work. ב-Navigator מסמנים את הגיליון ולוחצים Load. את Transform data שומרים לשיעור 2.
4. עוברים ל-Table view (סמל הטבלה בסרגל השמאלי). בשורת המצב בתחתית מופיע מספר השורות: 15,120.
5. חוזרים ל-Report view, מוסיפים Card וגוררים אליו את recordID. כנראה יופיע מספר ענק, כי Power BI סוכם מספרים כברירת מחדל: סכום מספרי הרשומות הוא 1,089,925,840. שואלים את הכיתה מה המספר הזה מודד.
6. בחץ של recordID בחלונית השדות בוחרים Count. אם מופיע 15K, משנים ב-Format visual את Display units ל-None ומקבלים 15,120.
7. שואלים "זה מספר החיות?" ולא עונים. זו משימה ג.
8. File → Save as, בתיקייה work, בשם L01\_Portal\_<שם>.pbix.

משימות התרגול ומה אמור לצאת:

| משימה | דקות | מה עושים | תשובה צפויה |
| --- | --- | --- | --- |
| א | 4 | תיקיות, העתקת קבצים, טעינה ושמירה | L01\_Portal\_<שם>.pbix בתיקייה work |
| ב | 3 | כרטיס עם Count של recordID | 15,120 |
| ג | 12 | בלשי נתונים ב-Table view: שורה בלי species, הערך NA, חיה שחוזרת, סוגי משתנים | ראו בהמשך |
| ד (אתגר) | 4 | גרירת plot לכרטיס | סכום 182,705 חסר משמעות. Count (Distinct) נותן 24 חלקות |

התשובות למשימה ג: ב-541 שורות אין species. ב-345 מהן note1 הוא 2 (החלקה נבדקה ולא נמצאו חיות), וב-190 הוא 4 (החלקה לא נבדקה). NA מופיע ב-115 שורות, וזה הקוד של Neotoma albigula, חולדת העצים לבנת הגרון. החיה שנלכדה הכי הרבה פעמים היא B2B328\_DM\_1, זכר של חולדת הקנגורו של מריאם: 30 פעמים בין 2016 ל-2018, תמיד בחלקה 24. במיון המשתנים, recordID הוא מזהה, year הוא זמן, wgt כמותי, ו-plot, species ו-sex קטגוריאליים. plot מטעה: הוא כתוב כמספר, אבל אין משמעות לממוצע של חלקות.

כרטיס היציאה: "שורה אחת בקובץ היא \_\_\_. המספר 15,120 גדול ממספר החיות, כי \_\_\_ וגם כי \_\_\_." שתי הסיבות שמחפשים: יש שורות בלי חיה, ואותה חיה נלכדת שוב ושוב. הכרטיסים פותחים את שיעור 2.

| מה קורה | מה עושים |
| --- | --- |
| תלמיד לחץ Transform data ונמצא בחלון אחר | Close & Apply בפינה השמאלית העליונה |
| קובץ הנתונים נפתח ישירות מ-Downloads | קודם מעתיקים ל-data, ורק אחר כך Get data |
| הקובץ נשמר במקום שגוי | Save as לתיקייה work |
| בכרטיס מספר ענק או 15K | מחליפים ל-Count, ומשנים את Display units ל-None |

אם ההדגמה נתקעת, פותחים את CP\_L01.pbix וממשיכים ממנו, או מציגים את צילומי המסך במצגת ועוברים על הצ'קליסט של התלמיד. מה שמחזיק את השיעור: בקובץ מתערבבות שלוש ישויות. רוב השורות הן לכידות, העמודה id מסמנת חיה, והשורות בלי species מתארות חלקה בלילה מסוים.

לעיון נוסף (באנגלית): [Get started with Power BI Desktop](https://learn.microsoft.com/en-us/power-bi/fundamentals/desktop-getting-started), [Text/CSV](https://learn.microsoft.com/en-us/power-query/connectors/text-csv).

## שיעור 2: מתכון שחוזר על עצמו

בסוף השיעור התלמידים מבינים ש-Power Query לא משנה את קובץ המקור. הוא שומר מתכון של צעדים ומריץ אותו מחדש בכל רענון. את כללי הניקוי לוקחים מהתיעוד של החוקרים, לא מהמראה של הנתונים.

ארבע תפיסות מוטעות עולות בשיעור הזה: "שיניתי את הקובץ", "NA הוא ערך חסר", "הפרופיל מראה את כל הנתונים" ו-"סדר הצעדים לא משנה".

### שיעור 4: אותו מתכון, מאגר חדש

## מה עדיין דורש בדיקה בתוכנה

הצעדים ב-Power BI נכתבו לפי התיעוד של Microsoft, לא מתוך הרצה על המחשבים שלך. אלה הנקודות שכדאי לבדוק בחזרה הראשונה:

- שמות התפריטים והצעדים בגרסה המותקנת, במיוחד אם הממשק בעברית.
- הסוגים ש-Changed Type בוחר ב-Portal (בקובץ xlsx הסוגים נקבעים לפי התאים, ולא לפי 200 השורות הראשונות של CSV, ולכן כדאי לבדוק אותם בתוכנה).  recordID, year, period, plot, hfl ו-wgt אמורים להיות מספרים שלמים ו-species טקסט. עשר עמודות ריקות ב-200 השורות הראשונות (ביניהן age ו-pregnant), והן נמחקות בשיעור 2 ממילא.
- איך year מוצג בציר ובטבלה: 2016 או 2,016.
- זמן הטעינה של BRFSS\_PA.csv במחשבי בית הספר, וש-data\_value מזוהה כמספר.
- ש-Remove Empty ב-species מסיר את כל השורות הריקות: 541 בקובץ המלא, 529 אחרי סינון ה-period, ונשארות 14,492 שורות.
- האם הכרטיס מציג קיצור (15K) כברירת מחדל, ואיפה מכבים אותו בגרסה שלך.
